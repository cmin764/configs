# Working in this repo

This is a personal dotfiles/config repo, **public on GitHub**. It exists so a
Mac migration takes minutes instead of an afternoon of reconstructing config
from memory. Read this before editing anything here.

## Invariants

- **Public repo: no secrets, no employer/client names.** Not in file contents,
  not in commit messages, not in comments. `apps/` configs and `.gitconfig`
  have already been through one redaction pass; don't reintroduce anything
  they scrubbed (`authInfo`, real client directory names, real emails other
  than the personal one).
- **Hand-edited configuration only.** No install logs, no plugin/extension
  inventories, no `brew leaves` dumps. If a file was generated by running a
  tool rather than editing a setting, it doesn't belong here -- regenerate it
  on the new machine instead.
- **Everything under `apps/` and `.claude/user/` is installed, not read in
  place.** `.claude/skills/config-sync/scripts/sync.py` is the only thing that
  copies, symlinks, or merges these files onto `~`. Never `cp` over a symlink
  target by hand; check `sync.py`'s `SYMLINKS` list first, since a plain
  overwrite there breaks the sync guarantee for everyone who clones this repo.
- **Symlinked files and their machine copies are the same file.** Editing one
  edits both. Don't "sync" a symlinked file; only the entries in `sync.py`'s
  `COPIES`/`MERGES` lists need that.
- **Some files intentionally diverge per machine** and must never be made to
  match: `~/.zprofile.local` (real secrets, gitignored), `~/.gitconfig.local`
  (per-client email overrides, gitignored), `.claude/user/settings.json` (the
  live copy on any given machine accumulates permission grants the template
  deliberately excludes).

## Where things live

See `README.md` for the file inventory and `.claude/skills/config-sync/SKILL.md`
for the sync mechanics and the fresh-Mac restore order -- both change often
enough that duplicating them here would just create a second copy to keep in
sync.

## CI vs. judgment

`.github/workflows/config-checks.yml` runs deterministic checks on every PR:
secret patterns, JSON/plist validity, hardcoded absolute home paths,
architecture-specific binaries. It does **not** judge whether a file is
genuinely hand-edited versus accumulated noise -- that's a human call made
during `config-sync --pull`, not a rule a regex can enforce. Don't try to grow
the CI workflow into that judgment; add a case to the skill instead.
